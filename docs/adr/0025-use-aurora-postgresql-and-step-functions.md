# Use Aurora PostgreSQL and Step Functions for durable state

GameWake stores transactional metadata, tenant-scoped resources, idempotency records, the append-only Wallet Ledger, and the business projection of World Operations in Aurora PostgreSQL Serverless v2. The MVP enables RDS Data API, uses an engine version that supports automatic pause at zero ACUs, and keeps connectionless callers from holding the cluster awake. Durable lifecycle orchestration uses Step Functions Standard: each execution has a stable operation-derived name, persists externally visible progress in PostgreSQL, and reconciles provider state before continuing. Step Functions execution semantics do not replace application idempotency, so every AWS, storage, game, notification, and payment effect receives a durable idempotency key and tolerates retries. This choice accepts database resume latency after idle periods in exchange for relational constraints, understandable financial transactions, low operational complexity, and near-zero idle compute cost.
