# Use one Role per Membership

GameWake gives each Membership at most one active Role Assignment. Assigning a new Predefined or Custom Role atomically replaces the previous Role; removing it leaves the Membership present but without permissions, while removing the Membership revokes participation entirely. This replaces the additive-assignment portion of ADR 0001 so a group of friends can answer “what can this person do?” from one visible Role, while policies remain allow-only and Resource Scope still limits that Role to an account or World.

The transition is compatibility-safe for persisted aggregates created by the additive model. Reads project an account-wide Owner first to preserve ownership, otherwise the newest assignment, and expose only that effective Role. The next explicit Role change persists exactly one assignment; an explicit Role removal clears legacy assignments so an older grant cannot reappear. Invitation acceptance is rejected for a User who already has a Membership. A rollback remains compatible because a single assignment is a valid subset of the previous representation, and the invariant that every Account retains an Owner remains non-bypassable.
